# 02: Label new turns

**What to build:** after each turn ends, a cheap model call places the new exchange in a **thread** (continue, resume, new main, new sub), writes its **gist** and flags auto **bookmarks** (landmark, branch point). The band now says where you are, in the thread's colour. Spec: [spec.md](../../claude-marks/spec.md), sections "Labeller", "UI" (colours and glyphs), "Band", "Status line", "Fields the MVP writes but doesn't use".

**Blocked by:** 01 (Track exchanges into the conversation file)

**Status:** resolved (merged to mvp; manual checks pending)

- [x] `turn.complete` awaits `next(e)`, enqueues the exchange and returns. A `$.clock` timer started in `session.start` drains the queue one call at a time, in conversation order. Nothing awaits the model inside a dispatch.
- [x] Each call is `$.model.complete` with `haiku`, `effort: 'low'`, the v3 labeller rules verbatim as the first cached block, and the dynamic part built as in the labeller prototype: threads so far (last 2 gists, current marked), the previous exchange (prompt, last 1200 chars of its reply), this exchange (joined prompts, up to 15 tool lines, reply head 2000 + tail 1000).
- [x] The reply is parsed and validated as the spec says (fence stripping, `{…}` extraction, clipped label, gist and why, unknown kinds dropped). Anything unusable becomes `continue` with no bookmarks.
- [x] Results apply per the spec: mod-minted ids `t1`, `t2`…; `resume` resolves through `mergedFrom`, unknown ids become `continue`; `new_sub` nests under the current main thread; no threads yet means `new_main`; at most one bookmark per kind, none recreated over a dismissed one; `bookmarkStats.*.flagged` counted; `by: 'labeller'` everywhere and `by: 'user'` values never overwritten.
- [x] An unanswered call (`api-error`, `empty-reply`, `aborted`) marks the exchange `failed`, retries once on the next drain, then leaves it on `continue`. A call the engine refuses to send stops the drain for the session, and the band hint reads `labeller off: <reason>`.
- [x] The band reads `● Main › Sub · here #n/N ◇ · click or /marks`, with the thread name and glyphs in the thread's colour (main threads by index from the spec's palette, sub-threads take their main's colour). Before the first label: `○ labelling… · click or /marks`. In fullscreen `here` follows the topmost exchange on screen.
- [x] The status line reads `/marks · N threads` and is set only when it changes.
- [ ] Build check: a completion started from the timer is not aborted when the next turn starts (if it is, re-queue `aborted` results). Record the finding on this ticket.

- `mod/hooks/lib/rules.ts`: the v3 rules, generated by `scripts/rules.mjs` from `labeller-prompt.v3.md`. `npm run check` fails if the copy drifts; `npm run rules` regenerates.
- `mod/hooks/lib/band.ts` (pure): `band(file, { fullscreen, hereId, hint }) -> Segment[] | undefined`, `colorOf(file, threadId)`, `glyphs(ex)`, `GLYPH`, `PALETTE`, `HINT`. `bandLine` is gone.
- `mod/hooks/lib/model.ts`: `currentThread(file, beforeId?)` (latest labelled exchange's thread; not yet live-only).
- `mod/hooks/lib/tracker.ts`: `exchangeOfRow(tracked, uuid)` (prompt, anchor or reply text row -> exchange id), `topmost(tracked, rows)`.
- `mod/hooks/register.tsx`: one `$.clock.every(500)` timer (started in `session.start`, previous one cancelled) runs `updateHere` and `drain`. `drain` calls `sync` first (decision 2: switch check on the timer tick), is guarded by `busy`, and drops a result whose conversation switched while the call ran. Plugin tests: `mod/tests/label.test.ts` (fake `model.complete` hook, answered by hand).

Deviations and notes:
- New `$.state` keys: `marks.here` (exchange id at the top of the viewport, null = latest) and `marks.labellerOff` (reason string, null = running). Both are reset on a conversation switch, so "off" lasts for that conversation only.
- `label.model` is the alias `'haiku'` (decision 3). RULES is the first prompt block with `cache: true`; `system` is not sent (decision 4).
- The retry rule counts all three unanswered reasons the same: `tries: 1` -> `failed`, re-tried at the head of the queue on the next tick; `tries: 2` -> placed by `continue` (no bookmarks, empty gist), `label.status` stays `failed`. `aborted` is therefore re-queued once, which is the build check's fallback; it is not re-queued without limit (a `timeoutMs` also resolves `aborted`).
- "Threads so far" leaves out empty gists (failed or unusable replies) instead of joining `""` as the prototype did.
- Prompts of one exchange are joined with `\n` for the labeller. An exchange missing from the row index (made before a hot reload; ticket 03 rebuilds the index) is sent with its excerpt as the prompt and an empty reply.
- A refused call is caught when `$.model.complete` rejects (in the kit, a `{ deny }` answer). The band hint shows the error's message. Pending exchanges stay `pending`; the queue keeps them.
- The status line keeps ticket 01's singular, `/marks · 1 thread`.
- The band is drawn as plain `Text` segments, not yet a `Button`; ticket 04 makes it the band click that opens the pane.
- A result applied after a switch: if the call returns before the switch is seen, the label lands in the old file (correct for that exchange); if the switch was seen first, the queue is empty and the result is dropped.
